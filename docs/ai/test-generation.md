# FlowForge Automation — Automated Test Case Generation

## 1. Automated Assertion & Fixture Synthesis

Automated testing is critical to safe workflow promotion across environments. Prior to Phase 13, creating pre-deployment test cases required manually typing mock trigger JSON payloads and defining step assertion rules (`EQUALS`, `CONTAINS`, `EXISTS`).

FlowForge Phase 13 introduces **AI Test Case Generation** (`POST /api/v1/ai/generate-tests/:workflowId`), automatically inspecting the workflow topology and generating production-ready test suites matching the Phase 12 schema (`CreateTestCaseSchema`).

---

## 2. Assertion Schema Compatibility

Every test fixture generated by FlowForge AI is fully compliant with the deterministic Phase 12 runtime test evaluator:

```typescript
export interface WorkflowTestCase {
  id: string;
  workflowId: string;
  name: string;
  description: string;
  triggerPayload: Record<string, any>;
  mockOutputs?: Record<string, any>;
  expectedStatus: "SUCCESS" | "FAILED";
  assertions: Array<{
    nodeId: string;
    fieldPath: string;
    operator: "EQUALS" | "CONTAINS" | "NOT_EQUALS" | "GREATER_THAN" | "LESS_THAN" | "EXISTS" | "NOT_EXISTS";
    expectedValue?: any;
  }>;
}
```

### Scenario Coverage

The AI generator produces scenarios across key operational boundaries:
1. **Happy Path (`HAPPY_PATH`)**: Realistic valid payloads with assertions ensuring all critical downstream steps achieve `SUCCESS`.
2. **Filter Boundary (`EDGE_CASE`)**: Payloads testing conditional nodes (e.g. empty emails, values below thresholds) verifying that executions terminate or divert as designed.
3. **Error Handling (`ERROR_HANDLING`)**: Corrupt data shapes verifying that error catches, notifications, or fallback paths behave predictably without unhandled exceptions.

---

## 3. Pre-Deployment Center Integration

In `/environments`, navigating to the **Automated Testing & Gates** tab reveals the **"Generate Tests with AI"** button (`[data-testid="btn-ai-generate-tests"]`).

When invoked:
1. FlowForge queries `/api/v1/ai/generate-tests/:workflowId`.
2. The AI generates scenarios and formats them into assertions mapped to the target workflow's node IDs.
3. Each test case is saved into the database and appears immediately in the fixture table.
4. Operators can click **"Run Test"** to dry-run the generated fixtures in the active environment.
